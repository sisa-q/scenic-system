# 第 4 章 · 服务层详解（Service，业务逻辑核心）

> 学习目标：看懂业务逻辑最重的一层——下单防超卖、订单状态机、支付回调、客流统计、天气降级。
> 结构：`service/` 放接口，`service/impl/` 放实现类。Controller 只调接口，实现可替换（面向接口编程）。

## 4.0 为什么要分 接口 + 实现？

```java
// service/OrderService.java（接口：定义能力）
public interface OrderService {
    Order createOrder(Order order, Long userId);
    void payOrder(Long id, Long operatorId, String role);
    // ...
}
// service/impl/OrderServiceImpl.java（实现：具体逻辑）
@Service
public class OrderServiceImpl implements OrderService { ... }
```
好处：解耦、方便测试（mock 接口）、符合 Spring 惯例。

## 4.2 ★ OrderServiceImpl —— 全项目最核心

### ① 下单防超卖（双保险）
```java
@Transactional
public Order createOrder(Order order, Long userId) {
    // 1. 参数/时段/票种校验
    // 2. Redis 分布式锁：ticket:slot:lock:{slotId}
    boolean locked = tryLock(lockKey, 15);   // setIfAbsent 互斥锁
    // 3. 锁内重新查库（双重检查），算余票
    int remaining = latest.getQuota() - latest.getBooked();
    if (remaining < order.getQuantity()) throw new RuntimeException("余票不足...");
    // 4. 生成订单（UUID 订单号、status=0、金额=单价×数量）
    return orderRepository.save(order);
}
```
**防超卖为什么可靠？**
- Redis 锁：同一时段的抢票请求串行化，避免并发读旧库存
- 数据库校验：锁内重查最新 booked，双重确认
- `@Transactional`：异常自动回滚
- **Redis 不可用时**：`tryLock` 返回 false → 仍走数据库校验（降级不阻塞，一致性靠事务保证）

### ② 支付（payOrder）
- 权限校验（只能付自己的订单）
- **超时失效**：`isPendingExpired` 判断超过 `pay.pay-timeout-minutes`（默认 30 分钟）→ `expirePendingOrder` 置 status=4
- 状态校验：0 才能支付；1 已付 / 3 已退 / 4 失效都拦截
- 锁内扣库存：`booked += quantity`，**付款成功才扣库存**（防占坑）

### ③ 核销（verify / useOrder）
- 管理员输入核销码 → 校验订单已支付（status=1）→ status=2 + useTime → 写 VerifyRecord → 驱动 FlowStat

### ④ 退款
- 游客 `applyRefund`：status 1→5（退款申请中）+ refundRequestTime
- 管理员 `refund`：status 5→3 + refundTime，**库存回滚**（booked -= quantity）
- `cancelRefund`：5→1（取消申请）

### ⑤ 支付超时自动失效（定时任务）
```java
@Scheduled(fixedDelay = 60000)   // 每分钟扫一次
public void autoExpirePending() {
    // 找出所有待支付且超时的订单 → status 0→4，释放占的库存
}
```

## 4.3 ★ PayServiceImpl —— 支付核心（已在第 1 章讲过 AlipaySigner）

```java
public PayResult createPayment(Long orderId, Long operatorId, String role) {
    // 校验订单归属 + 状态=0
    PayResult r = new PayResult(); r.setType("mock"); ...
    if (realAlipay() && alipaySigner != null) {   // 配置启用 alipay 时
        r.setRedirectUrl(alipaySigner.buildPagePayUrl(order, payProperties)); // 生成收银台 URL
        r.setType("alipay");
    }
    return r;
}

public String handleNotify(Map<String, String> params) {
    // 1. 幂等：trade_no 已存在直接返回 success
    // 2. 验签：verifyNotify（支付宝公钥验 RSA2 签名），失败返回 failure
    // 3. 状态校验：只处理 TRADE_SUCCESS / TRADE_FINISHED
    // 4. 金额校验：回调金额 == 订单金额（分）
    // 5. orderService.payOrder(...) 订单 0→1
    // 6. 落 PayTransaction（对账）
    return "success";
}
```
**回调安全**：验签 + 金额比对 + 幂等，是生产级支付回调的标准姿势（面试亮点）。

## 4.4 UserServiceImpl —— 登录安全

- 登录：`findByUsername` → `passwordEncoder.matches(明文, 哈希)` 校验
- 登录失败限流在 Controller 层用 Redis 计数（5 次锁 15 分钟）
- 注册：BCrypt 加密后入库；**旧明文密码自动迁移**（DataInitializer 启动时扫描）

## 4.6 FlowStatServiceImpl —— 客流统计

- 核销时累加：`FlowStat` 记录当前在园人数
- `getRealtime()`：返回当前人数/热力图数据（供 WebSocket 每 5 秒推）
- 无硬件依赖：内置**确定性客流模拟引擎**（双峰曲线 × 停留时长分布），没有真实核销时也能演示大屏
