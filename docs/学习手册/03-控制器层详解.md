# 第 3 章 · 控制器层详解（Controller，HTTP 入口）

> 学习目标：看懂每个接口的 URL、方法、参数、权限，以及 Controller 的固定套路。
> Controller 只做三件事：**收参数 → 调 Service → 返回 Result**，业务逻辑都在 Service 层。

---

## 3.0 Controller 固定套路（先记住）

```java
@RestController            // 声明是 REST 控制器（返回 JSON）
@RequestMapping("/api/xxx") // 该控制器所有接口的前缀
public class XxxController {
    @Autowired private XxxService xxxService;   // 注入业务层

    @GetMapping("/list")                          // GET 查询
    public Result list(@RequestParam(...) ...) {  // 查询参数
        return Result.success(xxxService.xxx());  // 统一返回 Result
    }
    @PostMapping("/add")                          // POST 新增
    public Result add(@RequestBody Xxx body) {    // JSON 请求体
        return Result.success(xxxService.add(body));
    }
}
```

## 3.1 十个控制器总览（40+ 端点）

### ① UserController —— 用户（`/api/user`）
| 端点 | 方法 | 说明 |
|---|---|---|
| `/login` | POST | 登录。**亮点**：登录失败限流（Redis 记 `login:fail:用户名`，5 次锁 15 分钟）；端角色强校验（游客端/管理端不能互登） |
| `/logout` | POST | 登出。**亮点**：JWT 加入 Redis 黑名单 `jwt:blacklist:jti`，立即失效 |
| `/register` | POST | 注册（BCrypt 加密） |
| `/info` | GET | 当前用户信息 |
| `/update` | PUT | 修改资料/密码 |

### ② SpotController —— 景点（`/api/spot`）
| 端点 | 方法 | 说明 |
|---|---|---|
| `/list` | GET | 景点列表（公开，游客首页） |
| `/detail/{id}` | GET | 景点详情（公开） |
| `/add` `/update` `/delete/{id}` | POST/PUT/DELETE | 景点维护（**仅管理员**，拦截器校验） |

### ③ TicketController —— 票种与时段（`/api/ticket`）
| 端点 | 方法 | 说明 |
|---|---|---|
| `/list` | GET | 票种列表（可按 spotId 过滤，公开） |
| `/slots` `/slots/spot` `/slot/{id}` | GET | 时段列表/按景点/单个时段（公开） |
| `/add` `/update` `/delete/{id}` | POST/PUT/DELETE | 票种维护（管理员） |
| `/slot/add` `/slot/update` `/slot/delete/{id}` | POST/PUT/DELETE | 时段维护（管理员） |

### ④ OrderController —— 订单（`/api/order`，核心）
| 端点 | 方法 | 说明 |
|---|---|---|
| `/list` | GET | 订单列表（分页 + 状态筛选 + 关键字；游客只看自己可见的） |
| `/detail/{id}` | GET | 订单详情 |
| `/create` | POST | 下单（**防超卖核心**：Redis 锁 + 库存校验，见第 4 章） |
| `/pay/{id}` | POST | 支付：返回 `{type, redirectUrl}`；alipay 跳收银台 / mock 直接确认 |
| `/refund-apply/{id}` | POST | 游客申请退款（status→5） |
| `/refund/{id}` | POST | 管理员审核退款（5→3，回滚库存） |
| `/cancel-refund/{id}` | POST | 游客取消退款申请 |
| `/batch-delete` | DELETE | 批量删除（管理员） |
| `/hide` | PUT | 游客隐藏订单 |

### ⑤ PayController —— 支付回调（`/api/pay`）
| 端点 | 方法 | 说明 |
|---|---|---|
| `/notify/alipay` | POST | **支付宝异步回调**（验签→改订单→落支付流水→返回 "success"） |
| `/mock/confirm/{id}` | POST | 模拟支付确认（演示用） |

### ⑥ VerifyController —— 核销（`/api/verify`，管理员）
| 端点 | 方法 | 说明 |
|---|---|---|
| `/list` | GET | 核销记录列表 |
| `/execute` | POST | 输入核销码 → 校验已支付订单 → 核销入园（status 1→2，驱动客流统计） |

### ⑦ FlowController —— 客流（`/api/flow`，管理员）
| 端点 | 方法 | 说明 |
|---|---|---|

| `/realtime` | GET | 实时客流（大屏初始数据；之后靠 WebSocket 每 5 秒推） |

## 3.2 权限是怎么控制的？（三层防线）

1. **拦截器白名单**（WebConfig）：公开接口直接放行
2. **JwtInterceptor**：非白名单必须带合法 token；`ADMIN_ONLY_PREFIXES` 前缀要求 role=admin
3. **Service 层业务校验**：如退款、支付订单归属校验（`operatorId.equals(order.getUserId())`）

> 面试点：权限设计 = 认证（你是谁，JWT）+ 授权（你能干什么，角色+接口前缀白名单）+ 业务校验（数据归属）。

## 3.3 前端如何调这些接口？

前端 `web/src/api/*.js` 用 axios 封装，例如：
```js
// order.js
export function payOrder(id) {
    return request.post(`/order/pay/${id}`)   // → POST /api/order/pay/{id}
}
```
请求拦截器自动带 `Authorization: Bearer <token>`，响应拦截器统一处理 `{code,msg,data}`。
