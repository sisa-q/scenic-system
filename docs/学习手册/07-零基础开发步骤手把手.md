# 第 7 章 · 零基础开发步骤手把手（从空目录到完整系统）

> 学习目标：把前面 6 章的知识按**真实开发顺序**串起来——如果从零重写这个项目，按下面 15 步走。
> 每一步都说明"做什么、在哪个文件、为什么要做"。

---

## 阶段零：环境准备（半天）

| 工具 | 版本 | 作用 |
|---|---|---|
| JDK | 21 | 后端运行环境（本项目在 `D:\bishe\tools\jdk-21.0.12+8`） |
| Maven | 3.9 | Java 依赖管理/构建 |
| IDEA | 任意 | 后端 IDE |
| Node.js | 18+ | 前端运行环境（Vite 需要） |
| MySQL | 8 | 数据库（本项目端口 3306） |
| Redis | 7 | 缓存/锁（本项目端口 6379，**没它也能跑**，降级） |

> 验证：`java -version`、`mvn -v`、`node -v` 都能输出版本即 OK。

## 第一步：创建 Spring Boot 工程（10 分钟）

IDEA：New Project → Spring Initializr → 选 Java 21 + Spring Boot 3.x
勾选依赖：Web / Data JPA / MySQL Driver / Lombok / WebSocket / Data Redis。
> 等价于本项目 `pom.xml` 里的依赖（第 1 章已逐个解释）。

## 第二步：配置 application.yml + 建库（10 分钟）

1. MySQL 建库：`CREATE DATABASE digital_ticket DEFAULT CHARSET utf8mb4;`
2. 写 `application.yml`：端口 8083、数据源、JPA ddl-auto=update、Redis、JWT、pay 配置（第 1 章）
3. **不需要手写建表 SQL**——JPA 启动时按实体自动建表（ddl-auto=update）

## 第三步：写实体 entity（半天）

按第 2 章的 10 个实体逐个写：User → ScenicSpot → TicketPolicy → TimeSlot → Order → PayTransaction → VerifyRecord → Evaluation → Notice → FlowStat。
> 顺序依据：先写被依赖的基础表（用户/景点），再写业务表（订单）。

## 第四步：写 Repository（半天）

每个实体配一个接口：`interface XxxRepository extends JpaRepository<Xxx, Long>`。
按业务需要加自定义查询方法（`findByXxx`），参考第 2 章 OrderRepository。

## 第五步：写 Service 接口 + 实现（1~2 天，核心）

按第 4 章逐个实现，**先实现 CRUD**（简单），再实现复杂业务：
1. 景点/票种/时段/公告/评价：纯 CRUD
2. 用户：注册（BCrypt）+ 登录（校验 + 发 token）
3. **订单：下单防超卖（Redis 锁 + 库存校验）→ 状态机 → 支付超时**
4. **支付：生成支付宝 URL + 回调验签 + 幂等**
5. 核销 + 客流统计
6. 天气三级降级

## 第六步：写 Controller（半天）

每个 Service 对应一个 Controller，只做"收参 → 调 Service → 返回 Result"（第 3 章）。

## 第七步：认证体系（半天，贯穿全局）

1. `JwtUtil`：生成/解析 token（第 1 章）
2. `JwtInterceptor`：校验 token + 管理员接口白名单（第 1 章）
3. `WebConfig`：注册拦截器 + 公开接口白名单
4. `CorsConfig`：跨域放行

## 第八步：全局横切（半天）

- `GlobalExceptionHandler`：统一异常 → Result
- `PasswordConfig`：BCrypt Bean
- `DataInitializer`：启动种数据（admin 账号 + 15 景点 + 票种时段 + 明文密码迁移）

## 第九步：亮点功能迭代（按答辩重要性排序，2~3 天）

1. **Redis 防超卖**：`ticket:slot:lock:{slotId}` 分布式锁 + 数据库双重校验（OrderServiceImpl）
2. **Redis 缓存三防**：`RedisCache`（防穿透/击穿/雪崩）+ 天气/景点接口接入
3. **订单状态机 + 支付**：6 态流转 + 2 分钟/30 分钟超时失效 + 支付宝沙箱回调
4. **客流 WebSocket**：FlowWebSocketHandler 每 5 秒推 + 前端 FlowScene 3D 大屏
5. **天气 WebSocket + 三级降级**：WeatherWebSocketHandler 30 分钟预警 + open-meteo→和风→模拟
6. **3D 地球全息导览**：threeScene 地球 + CSS2D 标注 + 天气标签
7. **登录安全**：失败限流 5 次锁 15 分钟 + JWT 黑名单登出

## 第十步：前端搭建（半天）

1. `npm create vite` 建 Vue3 工程
2. 装依赖：vant / element-plus / pinia / vue-router / axios / three
3. 配 `vite.config.js`：`/api` 代理到 `http://localhost:8083`
4. 写 main.js / App.vue / router / store（第 5、6 章）

## 第十一步：前端页面开发（2~3 天）

先写 api 封装（对应后端接口），再写页面（第 5、6 章逐个）：
- 游客端：首页 3D 地球 → 景点详情 → 下单 → 支付 → 订单 → 评价
- 管理端：登录 → 大屏 → 景点/票种/时段/订单/核销/公告/评价管理

## 第十二步：联调（1 天）

前端 8080/8081 + 后端 8083 一起跑，逐个接口对：
1. 浏览器 Network 看请求/响应
2. 常见问题：跨域（CorsConfig）、401（token）、404（路径不一致）、500（后端日志）

## 第十三步：测试（1 天）

`mvn test`：118 个单元/集成测试 + JaCoCo 覆盖率。
> 测试用 H2 内存库，不依赖 MySQL，CI 可跑。

## 第十四步：部署（1 天）

`deploy/` 下：Docker Compose（MySQL8 + Redis7 + 后端 + Nginx）+ 多阶段镜像 + 一键脚本。
安卓：`scenic-android/` HBuilderX 云打包 APK（web-view 套壳游客端）。

## 附：学习顺序建议（给你的路径）

如果你要**吃透**而不是重写，按这个顺序读：
1. 先读第 0 章（总览）→ 把项目跑起来
2. 沿一条业务流走通：注册 → 下单 → 支付 → 核销 → 大屏
3. 读后端：第 1 章（骨架）→ 第 2 章（数据）→ 第 3 章（接口）→ 第 4 章（业务）
4. 读前端：第 5 章（游客端）→ 第 6 章（管理端）
5. 回到第 7 章，用"15 步"检验自己能不能讲清每一步

> 面试准备：把第 1/4 章的"★"标记内容（Redis 防超卖、缓存三防、支付回调安全、订单状态机、天气降级、3D 大屏）背成 STAR 故事。
